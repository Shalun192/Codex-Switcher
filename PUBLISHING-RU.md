# Публикация проекта

Эта папка разделена на две части:

- исходный код в корне — его нужно хранить в Git-репозитории;
- `release-packages/` — готовые сборки, которые нужно прикреплять только к GitHub Release.

`release-packages/`, `node_modules/`, `vendor/`, `dist/`, авторизация, локальные профили, `.env` и сертификаты исключены через `.gitignore`. Не используйте `git add -f` для их принудительного добавления.

## Перед каждым релизом

```bash
pnpm install --frozen-lockfile
pnpm run check
pnpm audit --audit-level high
```

После сборки вычислите SHA-256 и приложите `SHA256SUMS.txt` к релизу. Загружайте только файлы из `release-packages/`, не папки данных приложения.

После публикации релиза обновите готовые файлы и номер версии на [странице загрузки](https://shalun.online/codex-switcher/), чтобы сайт и GitHub показывали одну актуальную версию.

## Рекомендуемые настройки GitHub

- основной репозиторий публичный, ветка по умолчанию `main`;
- включены Private vulnerability reporting, Dependabot alerts и Dependabot security updates;
- включено автоматическое удаление веток после merge;
- Actions имеют только read-доступ по умолчанию;
- для `main` включены pull request, обязательный CI и запрет force-push/deletion;
- `CODEOWNERS` требует проверки изменений владельцем проекта;
- секреты подписи добавляются только через GitHub Actions secrets, но никогда не коммитятся;
- релизы сначала создаются как draft и становятся публичными после проверки файлов и контрольных сумм.

Для Git-коммитов используется GitHub no-reply email, чтобы личный адрес не попадал в публичную историю.
